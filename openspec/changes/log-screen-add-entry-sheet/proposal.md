# Proposal: Log Screen + Add Entry Sheet (Phase 1)

## Intent

A parent tracking an infant's sleep has no way to record or review nights. The app is a bare scaffold: one placeholder route, no theme, no state, no navigation shell. Phase 1 delivers the core loop — see logged sleeps, add a new one — as the foundation every later phase (analysis, persistence) builds on. Success: a parent can log a night in under 30 seconds and read the week at a glance.

**Native module**: none added. `@expo/ui`, `@expo/vector-icons` (installed by the user during the session), and `expo-router` are already installed; the change runs in Expo Go and needs no development build.

**MVP directive (user, binding):** functional MVP only, nothing fancy. Keep components, tokens and validation minimal; skip anything not needed to see, add and validate entries.

## Scope

### In Scope

- Tabbed shell (`Log`, `Analysis`) with a thin placeholder Analysis screen.
- Log screen: scrollable entry list (newest first), `THIS WEEK` label, latest entry highlighted, duration pill + progress bar, inline notes, empty state, FAB.
- Add Entry sheet as an Expo Router `formSheet` route: date, sleep time, wake time, optional notes, validation, primary save action.
- In-memory entries store (React context + `useEntries()`), overnight duration derivation.
- `src/theme.ts` design tokens and `src/utils/` helpers (date, duration, id).

### Out of Scope (non-goals)

Persistence/storage · analysis charts or any Analysis content · edit/delete entries · baby profile management · web platform · dark mode · seed data · tests (no runner configured).

## Capabilities

### New Capabilities

- `sleep-entry-log`: entry data model, in-memory store, ordering, duration derivation, list/empty-state presentation.
- `add-entry-sheet`: sheet presentation, form fields, validation rules, save/dismiss behavior.
- `app-navigation`: tab shell, route/screen separation, sheet route registration.
- `theme`: design tokens (colors, typography, spacing, radii, layout constants) and their usage contract.

### Modified Capabilities

None.

## Approach

Thin routes in `src/app/`; all UI and styles in `src/screens/` and `src/components/`.

| Layer | Path | Role |
|---|---|---|
| Routes | `src/app/(tabs)/index.tsx`, `(tabs)/analysis.tsx`, `(tabs)/_layout.tsx`, `add-entry.tsx`, `_layout.tsx` | Navigation only; render screens |
| Screens | `src/screens/log/`, `src/screens/analysis/`, `src/screens/add-entry/` | Layout + styles |
| Components | `src/components/` | Entry card, empty state, FAB, form field |
| State | `src/context/entries-context.tsx` | Provider in root `_layout.tsx`, `useEntries()` hook |
| Tokens | `src/theme.ts`, `src/utils/` | Inside `src/` so the `@/*` alias resolves (user-approved reading of "root of the project") |

Decisions: JS `Tabs` from `expo-router` (not native tabs); `formSheet` route with numeric detents (provider must sit in root `_layout.tsx`); icons from `@expo/vector-icons` (Ionicons / FontAwesome6, already imported in the user's tab scaffold), no `expo-symbols`; system serif/monospace via `Platform.select`; light theme only; iOS + Android only.

Model: `SleepEntry { id, date, sleepTime, wakeTime, notes?, createdAt }` (serializable strings). Duration: `wake > sleep ? wake - sleep : wake + 1440 - sleep`. Equal times invalid; future dates and duplicates allowed.

## Affected Areas

| Area | Impact | Description |

## Risks

| Risk | Likelihood | Mitigation |
|---|---|---|
| Android date/time dialog layered over `formSheet` unverified | Med | Mount picker only while open; manual check early; fallback to inline `presentation` on Android |
| Keyboard covers notes input in sheet | Med | `KeyboardAvoidingView` + `ScrollView`, numeric detents (not `fitToContents`) |
| `typedRoutes` types generated by dev server | High | Run `npx expo start` once before `npx tsc --noEmit`; record as a verify prerequisite |
| SDK 57 docs vs shipped code mismatch | Med | Verify against installed `.d.ts`, never from memory |
| React Compiler enabled | Med | No manual `useMemo`/`useCallback` |
| No test runner | High | Verification = `npx expo lint` + `npx tsc --noEmit` + manual walkthrough |
| Scope creep into Phase 2 | Med | Non-goals listed above are binding |

## Rollback Plan

All work is additive plus three route moves, with no native or config changes. The only dependency change is the user's own `@expo/vector-icons` addition to `package.json` / `package-lock.json`, which is not part of this change's revert. Revert with `git revert` of the change commit(s) (or `git checkout -- src/`), restoring root `_layout.tsx`, `index.tsx`, and `analysis.tsx`; delete `src/app/(tabs)/`, `src/app/add-entry.tsx`, `src/screens/`, `src/components/`, `src/context/`, `src/utils/`, `src/theme.ts`. No data migration, no `npx expo install --fix` needed.

## Dependencies

None added by this change (`@expo/vector-icons` is already installed by the user). Prerequisite: `npx expo start` run once so `.expo/types/router.d.ts` exists.

## Success Criteria

- [ ] Tabs navigate between Log and Analysis; Analysis renders a placeholder.
- [ ] Empty state shows when no entries exist; FAB opens the Add Entry sheet.
- [ ] Saving a valid entry dismisses the sheet and prepends it to the list with a correct duration (including overnight).
- [ ] Invalid input (missing field, sleep == wake) blocks save with visible feedback.
- [ ] Latest entry is visually highlighted; notes render inline when present.
- [ ] `npx expo lint` and `npx tsc --noEmit` pass; verified manually on iOS and Android.
