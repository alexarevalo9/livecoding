# Proposal: AI Analysis Screen (Phase 2)

> Size note: over the 450-word guidance by design. Binding launch directives enumerate the model discrepancy, the client-side key risk, the error taxonomy, rollback, the native-module statement, and three open questions. Prose is kept terse.

## Intent

Phase 1 makes logging write-only: a parent records nights and gets nothing back. The Analysis tab turns the last 5 logged nights into a plain-language weekly summary with at least two key stats and one actionable tip, generated by Claude.

**Native module**: none. Global `fetch` only — runs in Expo Go, no development build, no new dependency (an Anthropic SDK is rejected for RN).

**Status**: planning only. No implementation until Phase 1 (`log-screen-add-entry-sheet`) lands.

## Scope

### In Scope

- Analysis tab screen that auto-starts the analysis on open, with four states: loading (skeleton placeholders), success, error (with Retry), empty (zero entries → no request).
- Analysis util outside `src/app/` wrapping `POST https://api.anthropic.com/v1/messages`: prompt construction, defensive JSON parse/validation, typed result `{ summary, stats (≥2), tip }`, timeout + unmount abort.
- Distinct user-facing errors for: missing key, network/offline, 401, 429, 5xx, malformed response, timeout.
- API key from config only (`process.env.EXPO_PUBLIC_ANTHROPIC_API_KEY`), never committed; model pinned as one named constant.

### Out of Scope

Persisting analysis results · streaming · multi-turn chat · backend proxy · charts · test infra · any change to Phase 1's entry model or store.

## Capabilities

### New Capabilities

- `analysis-tab`: auto-start trigger, input selection, loading/success/error/empty states, retry.
- `llm-analysis-client`: request contract, key/model config, typed result, parse validation, error taxonomy, cancellation.

### Modified Capabilities

None. `openspec/specs/` is empty (Phase 1 unarchived); Phase 1's "Analysis renders a placeholder" requirement is superseded by `analysis-tab` on archive.

## Approach

Route → screen → hook → util, mirroring Phase 1's layering and reusing `src/theme.ts`.

| Layer | Path |
|---|---|
| Route | `src/app/(tabs)/analysis.tsx` |
| Screen | `src/screens/analysis/AnalysisScreen.tsx` |
| Hook | `src/screens/analysis/use-analysis.ts` |
| Util | `src/utils/anthropic.ts` (or `src/services/`) |
| Config | `src/config/anthropic.ts` (key lookup + `ANTHROPIC_MODEL`) |

Input: the first 5 items of `useEntries().entries` — Phase 1 guarantees newest-first via prepend, so no sorting and no store change. These are the 5 most recently **logged** entries, not the 5 most recent sleep dates; fewer than 5 is valid.

The route path follows whichever layout Phase 1 lands: `src/app/(tabs)/analysis.tsx`, else today's `src/app/analysis.tsx`.

## Risks

| Risk | Likelihood | Mitigation |
|---|---|---|
| `EXPO_PUBLIC_*` key is inlined into the JS bundle and extractable | High | Accepted, brief-driven; throwaway key, proxy is a non-goal |
| Plain `.env` is **not** git-ignored (`.gitignore` has only `.env*.local`) | High | Use `.env.local`; commit `.env.example`; add `.env` to `.gitignore` |
| Model ID discrepancy (see Unresolved #1) | High | Single named constant; needs user confirmation |
| Model returns prose or invalid JSON | Med | Ask for JSON only; validate; map to malformed-response state |
| Hung request leaves the tab spinning | Med | `AbortController` timeout + abort on unmount |
| Phase 1 not yet implemented | High | Apply blocked until `useEntries()` and `src/theme.ts` exist |

## Rollback Plan

Additive plus one placeholder route reverted. `git revert` the change commit(s), delete `src/screens/analysis/`, the API util and `src/config/`, restore the Phase 1 placeholder `analysis.tsx`, remove `.env.local`/`.env.example`. No dependency, native, `app.json`, or persisted data changes — no migration.

## Dependencies

- **Blocking**: Phase 1 applied — `useEntries()`, `SleepEntry`, `src/theme.ts`, `(tabs)` layout.
- **Blocking for runtime verification**: an Anthropic API key supplied by the user.
- No npm packages added.

## Success Criteria

- [ ] Opening Analysis with ≥1 entry immediately shows skeletons, never a blank screen.
- [ ] Success state shows a plain-language summary, ≥2 key stats, and 1 actionable tip.
- [ ] Exactly the 5 most recently logged entries are sent; <5 works; 0 shows the empty state with no request.
- [ ] Each error class renders a distinct message with a working Retry; a missing key is explicit, not a crash.
- [ ] No key literal in source; unmounting mid-request cancels cleanly; `npx expo lint` and `npx tsc --noEmit` pass.

## Unresolved (for user decision)

1. **Model ID** — `claude-sonnet-4-5-20250929` (the user's "Sonnet 4.5", orchestrator's decision) vs the brief's `claude-sonnet-4-20250514`. Recommended: keep the user's, confirm before apply.
2. **Re-run policy** — re-analyze on every tab focus vs first open plus manual refresh. Recommended: first open + explicit Refresh/Retry, and auto re-run only when the 5-entry input changed.
3. **Caching** — keep the last result in memory while the 5-entry input is unchanged. Recommended: yes, in-memory only (no persistence).
